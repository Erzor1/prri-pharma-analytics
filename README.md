## 📌 1. Проблема бизнеса и ценность проекта

Аптечные сети, фармдистрибьюторы, тендерные отделы госзакупок и дирекции по качеству (QA/R&D) регулярно сталкиваются с отзывами серий лекарственных средств по предписаниям Росздравнадзора. Каждая отозванная серия — это прямые убытки на логистику возврата, заморозку складского стока, штрафы по контрактам и репутационные потери.

**Почему стандартная статистика «по количеству отозванных серий» не работает?**  
В государственном реестре Росздравнадзора в одной таблице смешаны:
1. Полиграфические опечатки на вторичной пачке (`Маркировка`, `Упаковка`);
2. Технологические отказы лекарственной формы (`Растворение`, `Однородность дозирования`, `Механические включения`);
3. Критические угрозы жизни и здоровью пациента (`Родственные примеси`, `Стерильность`, `Бактериальные эндотоксины`, `Пирогенность`, `Количественное определение`);
4. Письма со статусом `Разрешение реализации` (`208` записей) — которые вообще не являются браком, а снимают ранее наложенный карантин после перепроверки.

**Решение:** В проекте разработана взвешенная скоринговая модель **PRRI (Pharma Recall Risk Index)** и метрика доли технологического брака **TDR (Technological Defect Share, %)**, которые автоматически отделяют случайный упаковочный сбой от системного провала технологии производства на заводе.

## 📐 3. Математическая модель скоринга: PRRI и доменные метрики

### 3.1. Индекс риска забраковки — **PRRI (Pharma Recall Risk Index)**
Для каждого инцидента забраковки $i$ рассчитывается взвешенный балл риска:

$$\text{PRRI} = \sum_{i=1}^{N} \left( W_{\text{defect}, i} \times W_{\text{action}, i} \times W_{\text{chronic}, i} \times e^{-\lambda \cdot \Delta t_i} \right)$$

1. **$W_{\text{defect}, i}$ — Доменный вес критичности дефекта (классификация химика-аналитика):**
   - **Level 1 — Packaging & Labeling (`вес 1.0`):** `Маркировка`, `Упаковка`, `Комплектность`, `Срок годности на пачке`. Логистический или полиграфический сбой, не влияющий на эффективность и безопасность самой таблетки/раствора.
   - **Level 2 — Technological & Pharmacopoeial Form (`вес 2.5`):** `Растворение`, `Распадаемость`, `Однородность дозирования`, `Средняя масса`, `Описание`, `Цветность`, `Прозрачность`, `Механические включения`, `pH`, `Вода / Потеря в массе при высушивании`, `Осмоляльность`. Сбой техпроцесса грануляции, таблетирования, нанесения оболочки или фильтрации.
   - **Level 3 — Critical Safety, API & Microbiology (`вес 5.0`):** `Родственные и посторонние примеси` (включая специфические продукты деградации: *каптоприла дисульфид*, *салициловая кислота*, *даунорубицина агликон*), `Количественное определение`, `Подлинность`, `Микробиологическая чистота`, `Стерильность`, `Бактериальные эндотоксины`, `Пирогенность`, `Аномальная токсичность`. Прямая угроза здоровью пациента.
2. **$W_{\text{action}, i}$ — Строгость регуляторной меры:**
   - `Отзыв` / `Изъятие` / `Прекращение обращения` = **$1.5$**; `Приостановление реализации` / `Информационное` = **$1.0$**; `Разрешение реализации` = **$0.0$** (исключено из событий брака).
3. **$W_{\text{chronic}, i} = 1 + 0.25 \cdot \ln(N_{\text{mfg, cat}})$ — Фактор системности (хронической серийности):**
   - Повышающий коэффициент для технологических и критических дефектов (Level 2–3), если у завода забраковано $N > 1$ серий по одной и той же категории брака (индикатор неотвалидированного техпроцесса или проблемной смены поставщика АФС).
4. **$e^{-\lambda \cdot \Delta t_i}$ — Временное затухание (Recency Decay):**
   - Инциденты за последние 12 месяцев входят с максимальным весом **$1.0$**, более старые экспоненциально затухают ($\lambda = 0.50\text{ год}^{-1}$, $\Delta t_{\text{eff}} = \max(0, \text{age\_years} - 1)$).

### 3.2. Дополнительные метрики
- **TDR (Technological Defect Share, %):** доля технологического и критического брака ($\text{Level 2} + \text{Level 3}$) среди всех верифицированных несоответствий завода или лекарственной формы.
- **Series-per-Incident Ratio (Глубина поражения):** среднее количество отозванных серий, приходящееся на одно информационное письмо Росздравнадзора.

## 🗄️ 4. Аналитические витрины SQL (`sql/views.sql`)

Все витрины написаны на совместимом ANSI SQL (работают идентично в **PostgreSQL 16** и **SQLite 3.37+**) с активным использованием **CTE (`WITH ... AS`)** и **оконных функций**:

1. **`v_monthly_defect_dynamics`** — помесячная динамика брака с расчетом MoM-прироста через `LAG()`, 3-месячного скользящего среднего `AVG() OVER (ORDER BY year_month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` и накопительного итога с начала года (`YTD SUM() OVER (PARTITION BY year ...)`).
2. **`v_manufacturer_risk_ranking`** — ранжирование 366 производителей (`DENSE_RANK() OVER`), расчет кривой Парето (`SUM(prri_score) OVER (ORDER BY prri_score DESC) / SUM(prri_score) OVER ()`) и автоматическое определение главной («узкой») технологической проблемы каждого завода через `ROW_NUMBER() OVER (PARTITION BY manufacturer_clean ORDER BY category_batches DESC)`.
3. **`v_dosage_form_defect_matrix`** — R&D-матрица «Лекарственная форма × Категория дефекта» с долями внутри каждой технологической группы (`SUM() OVER (PARTITION BY dosage_form_group)`).
4. **`v_chronic_drug_recidivism`** — отслеживание цепочек повторных писем РЗН по одной и той же паре `(Завод + Препарат + Дефект)` через `LAG(letter_date) OVER (PARTITION BY manufacturer_clean, trade_name, defect_category ORDER BY letter_date)`.

## 🔬 5. Ключевые продуктовые и R&D-инсайты (на реальных данных 2020–2026)

### Инсайт 1: Продуктовая валидация матрицы `PRRI × TDR` (Кейс «Юнифарм Инк»)
У компании **«Юнифарм Инк»** в реестре числится **135 отозванных серий**. В обычном отчете по числу серий этот производитель попал бы в топ-5 антирейтинга рынка. Однако наш классификатор показывает, что **100% из 135 серий отозваны исключительно по показателю «Маркировка и упаковка» (`TDR = 0.0%`)**, без единой претензии к качеству самой таблетки. Матрица `PRRI × TDR` автоматически изолирует его в категорию **`Packaging Risk`**, отделяя от площадок с реальным технологическим риском (**ООО «ПРАНАФАРМ»** — `TDR = 98.5%`, **ПАО «Биосинтез»** — `TDR = 99.3%`, **АО «ВЕРОФАРМ»** — `TDR = 99.1%`, **ООО «Озон»** — `TDR = 96.2%`).

### Инсайт 2: Закон Парето в фармацевтических рисках
Топ-12 производственных площадок из 366 (**всего 3.3% производителей**) генерируют **60.22%** всего верифицированного индекса технологического риска `PRRI` на рынке РФ.

### Инсайт 3: Два архетипа технологического брака в витрине рецидивов
Сочетание числа писем РЗН во времени (`unique_letters_count`) и глубины поражения (`series_per_letter_ratio`) выявило два противоположных сценария:
- **Хроническая нестабильность рецептуры и техпроцесса (высокий риск для новых закупок):**
  - *Эналаприл (ПАО «Биосинтез»):* **47 разных писем РЗН** (108 серий за 2023–2024 гг.) по «Родственным примесям» — гидролиз эналаприла малеата до эналаприлата и внутримолекулярная циклизация в дикетопиперазин из-за влажности и неоптимального pH микроокружения таблетки.
  - *Цитрамон П (ОАО «ДАЛЬХИМФАРМ»):* **25 писем РЗН** (27 серий за 2020–2026 гг.) — автокаталитический гидролиз ацетилсалициловой кислоты до свободной салициловой кислоты.
  - *Спиронолактон в капсулах (ООО «ПРАНАФАРМ»):* **19 писем РЗН** (32 серии за 2025–2026 гг.) по показателю «Растворение» — проблема гранулометрии гидрофобной АФС (BCS Class II) или сшивки желатина капсульной оболочки.
- **Единоразовый глобальный отзыв партии (One-off Sweep):**
  - *Ранитидин (ООО «Озон»):* всего **2 письма**, но сразу **109 серий** (`54.5 серии/письмо`) в марте 2021 г. в рамках глобального отзыва ранитидина из-за примеси нитрозамина NDMA.

## 🚀 7. Быстрый старт и деплой

### Вариант А: Запуск в Docker Compose (PostgreSQL 16 + Streamlit + Daily Scheduler)
```bash
git clone https://github.com/<your-username>/prri-pharma-analytics.git
cd prri-pharma-analytics
docker compose up -d --build
```
После старта автоматически поднимется **PostgreSQL 16**, выполнится ETL-пайплайн (`src/pipeline.py`), развернутся SQL-витрины (`sql/views.sql`) и веб-дашборд станет доступен по адресу `http://localhost:8501`.

### Вариант Б: Локальный запуск (Python 3.10+, автоматический SQLite fallback)
```bash
python -m venv .venv
# Windows:
.\.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt

# Полный цикл: парсинг API РЗН -> очистка и расчет PRRI -> инициализация БД и SQL-витрин
python -m src.pipeline

# Запуск интерактивного дашборда
streamlit run app.py
```

### Настройка автодеплоя на VPS (CI/CD GitHub Actions)
Пайплайн `.github/workflows/deploy.yml` при каждом `git push origin main` прогоняет проверку кода и обновляет контейнеры на VPS по SSH. Для включения добавьте в репозитории GitHub (`Settings -> Secrets and variables -> Actions`) секреты:
- `VPS_HOST` — IP-адрес вашего VPS
- `VPS_USER` — имя пользователя SSH (например, `root` или `deploy`)
- `VPS_SSH_KEY` — приватный SSH-ключ
- `VPS_PORT` — порт SSH (по умолчанию `22`)
- `VPS_APP_DIR` — директория проекта на сервере (по умолчанию `/opt/prri-analytics`)
